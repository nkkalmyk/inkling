# Как участвовать

Спасибо, что хотите помочь. Коротко; полные правила и объяснения — в [`AGENTS.md`](AGENTS.md) (раздел «Правила работы с репозиторием»), они одинаковы для людей и ИИ-агентов.

## Собрать и проверить

```bash
brew install xcodegen
xcodegen generate && xcodebuild -scheme Inkling -destination 'platform=macOS' build test
```

Нужны Mac на Apple Silicon, macOS 26+ и Xcode 26+. Без `Config/Signing.xcconfig` сборка подписывается ad-hoc, этого достаточно.
Живые тесты с настоящими Claude, Codex и Ollama по умолчанию выключены (тратят лимит), как их включить — в [`AGENTS.md`](AGENTS.md).

## Правила

1. Ветка от свежего `main` на одну задачу, потом pull request. В `main` напрямую не коммитьте и историю не переписывайте.
2. Перед PR сборка без предупреждений и зелёные тесты. Меняете поведение — добавьте тест.
3. Сообщения коммитов и описание PR — по-русски, коротко и по сути. В описании PR укажите, что проверено и что нет.
4. Видимое изменение — строка в `CHANGELOG.md`. Решение, меняющее ТЗ, — `SPEC.md`, раздел 13.
5. Интерфейс только на русском; идентификаторы в коде на английском. Новые экраны — на компонентах `Inkling/DesignSystem/` ([`docs/design-system.md`](docs/design-system.md)).
6. Не добавляйте зависимости (SPM, CocoaPods, сеть). Сторонний код — только JS-ассеты в бандле с зафиксированными версиями.
7. Не коммитьте личные данные: свои конспекты и фото, `TestData/real/`, ключи, `Config/Signing.xcconfig`, свою почту и пути. В примерах и тестах — синтетические данные.

## Нашли уязвимость или утечку

Не открывайте публичный issue: напишите владельцу репозитория через GitHub (Security → Report a vulnerability).
