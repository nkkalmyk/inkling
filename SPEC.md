# Inkling: техническое задание

> Рабочее название при составлении ТЗ было «Конспектор»; приложение называется Inkling (см. раздел 13). Ниже текст ТЗ как был.

Собери мне нативное macOS-приложение «Конспектор». Я загружаю в него фотографии рукописных конспектов (химия, математика, физика) и PDF со слайдами преподавателя. Приложение переводит их в цифровой текст, собирает чистый конспект и готовит вопросы, тест и карточки для самопроверки.

Сначала прочитай всё ТЗ, задай вопросы, если что-то неясно, и предложи план по этапам (черновик плана в конце). Код пиши после того, как я утвержу план. Собирай по шагам: каждый этап должен компилироваться, проходить тесты и запускаться, прежде чем переходить к следующему.

## 1. Окружение
- Mac на Apple Silicon (M5), последняя macOS, Xcode установлен.
- Swift + SwiftUI, минимум macOS 14 (можно использовать `@Observable`). AppKit там, где SwiftUI не хватает (Камера непрерывности, печать в PDF).
- Проект генерируется через XcodeGen (`project.yml`), чтобы пересобирать из консоли. Если XcodeGen не установлен, поставь через brew.
- App Sandbox выключен: приложение запускает внешние CLI.
- Сторонних зависимостей по минимуму. В бандл кладутся KaTeX с расширением mhchem и JS-рендерер Markdown (например, markdown-it), всё работает офлайн. Версии зафиксированы, файлы лежат в репозитории.

## 2. Откуда берётся «ИИ»
Своих API-ключей нет. Приложение вызывает уже установленные консольные утилиты в headless-режиме:
1. **Gemini CLI** (`gemini`), основной движок. Вход через Google-аккаунт с подпиской AI Pro.
2. **Claude Code** (`claude -p`), запасной движок. Вход через подписку Claude Pro.

### 2.1. Архитектура
- Протокол `AIEngine` и две реализации, `GeminiCLIEngine` и `ClaudeCodeEngine`. Позже можно будет добавить Ollama.
- Запрос: текст промпта, список файлов-картинок, ожидаемый формат (текст / JSON), таймаут, модель. Ответ: текст, имя движка и модели, время выполнения.
- Ошибки как типизированный enum: `binaryNotFound`, `notAuthenticated`, `rateLimited(resetAt: Date?)`, `timeout`, `cancelled`, `invalidOutput`, `processFailed(exitCode, stderr)`. В UI для каждой ошибки понятное русское сообщение, сырой stderr доступен по раскрытию.

### 2.2. Сначала разведка CLI (этап 0)
**Не доверяй моим предположениям о флагах.** До кода сам выполни `gemini --help` и `claude --help`, проведи эксперименты на реальной картинке и запиши выводы в `docs/cli-notes.md`: точные команды, формат JSON-ответа, примеры stderr при ошибках. Мои гипотезы, которые нужно подтвердить или опровергнуть:
- Gemini: `gemini -p "<промпт>" --output-format json`, картинка передаётся как `@./page.jpg` в тексте промпта (путь относительно рабочей папки), модель выбирается через `-m`, текст ответа лежит в поле `response`.
- Claude: `claude -p "<промпт>" --output-format json --allowedTools Read --model …`, картинку модель читает инструментом Read из рабочей папки. Ответ лежит в поле `result`, признак ошибки в `is_error`. Проверь, есть ли флаг структурированного вывода по JSON-схеме (например, `--json-schema`). Если есть, используй его на этапе 3.
- Как оба CLI сообщают об исчерпании лимита: коды выхода и тексты (`429`, `RESOURCE_EXHAUSTED`, `quota`, `usage limit`, «limit reached … resets at …» и т. п.). Шаблоны распознавания лимита храни списком, который легко дополнить, и покрой тестами на реальных примерах stderr.
- Есть ли у Gemini CLI механизм «доверенных папок» или подтверждений, который ломает headless-запуск во временной папке.

### 2.3. Изоляция запусков
Headless-запуск не должен зависеть от моих глобальных настроек: CLAUDE.md, GEMINI.md, MCP-серверов, хуков. Используй флаги, найденные на этапе 0: без MCP, без пользовательских настроек и памяти, для Claude только инструмент Read, никаких инструментов записи и шелла. Логин при этом должен работать. Если какой-то изоляции добиться нельзя, напиши об этом в `docs/cli-notes.md`.

### 2.4. Поиск бинарников
GUI-приложения не наследуют PATH из шелла.
- Сначала проверь известные места: `/opt/homebrew/bin`, `/usr/local/bin`, `~/.npm-global/bin`, `~/.local/bin`, `~/.claude/local`, `~/.nvm/versions/node/*/bin`, `~/.volta/bin`, `~/.bun/bin`.
- Затем спроси шелл. Учти, что `zsh -lc` не читает `.zshrc`, а nvm обычно подключается именно там. Нужен вариант `/bin/zsh -ilc 'command -v gemini'`. Вывод обрамляй маркерами, потому что интерактивный шелл может печатать мусор.
- **Важно:** `gemini` — это node-скрипт с `#!/usr/bin/env node`. При запуске из GUI в `PATH` процесса нужно добавить каталог бинарника и каталог с `node`, иначе запуск упадёт с «env: node: No such file or directory». Для Claude проверь аналогично.
- Найденные пути видны в настройках и меняются вручную. Ручной путь важнее автопоиска.

### 2.5. Запуск процесса
- Каждый вызов идёт в отдельной временной папке в `NSTemporaryDirectory()`, вне iCloud. Там лежат только нужные изображения. После вызова папка удаляется. При ошибке её можно сохранить для отладки, если включён флаг в настройках.
- Таймаут настраивается, по умолчанию 120 с на страницу. Для сборки конспекта таймаут отдельный и растёт с объёмом.
- Отмена убивает всю группу процессов: node порождает дочерние процессы. Сначала SIGTERM, через 3 с SIGKILL.
- Параллельно не больше 2 вызовов (настройка 1–2), чтобы не сжигать лимиты.

### 2.6. Повторы и запасной движок
- **Лимит:** остаток задания сразу уходит на запасной движок, если включено автопереключение. Основной помечается «лимит до HH:MM», если время известно из stderr. До этого времени новые задания сразу идут на запасной, и это видно в UI.
- **Таймаут, пустой или невалидный ответ:** один повтор на том же движке, потом запасной движок, если автопереключение включено.
- **Нет бинарника, нет логина:** без повторов, понятная ошибка со ссылкой на настройки.
- В `meta.json` для каждой страницы и каждого артефакта записывается, каким движком и какой моделью он получен.

## 3. Источники в лекции
В лекции два раздела источников, любой из них может быть пустым:
- **«Мой конспект»**: фото рукописи (JPG, PNG, HEIC) и PDF-сканы тетради.
- **«Слайды»**: PDF преподавателя (презентации, методички), обычно на 40–80 страниц.

### 3.1. Импорт
- Перетаскивание файлов из Finder и из «Фото». Из «Фото» часто приходит не файл, а обещание файла (file promise), это нужно поддержать.
- Кнопка «Добавить файлы…» (стандартный диалог).
- Вставка из буфера обмена (⌘V), в том числе через универсальный буфер с iPhone.
- **Камера непрерывности:** пункт меню и контекстного меню «Импорт с iPhone → Сфотографировать / Сканировать документы». Страницы попадают в текущий раздел лекции.
- При импорте PDF приложение спрашивает раздел, если это не очевидно: в PDF с текстовым слоем это, скорее всего, слайды.
- Порядок страниц меняется перетаскиванием, лишние страницы удаляются. Фото по умолчанию сортируются по дате съёмки из EXIF.

### 3.2. Предобработка фото рукописи
- Поворот по EXIF, конвертация HEIC и страниц PDF-сканов в JPEG.
- **Автообрезка и выпрямление перспективы** через Vision (`VNDetectDocumentSegmentationRequest` или `VNDetectRectanglesRequest`) и Core Image (`CIPerspectiveCorrection`), без сторонних библиотек.
- Ручная правка: «Использовать оригинал» (отменить обрезку), поворот на 90° влево и вправо, при желании правка углов рамки.
- Уменьшение до ~2000 px по длинной стороне, качество JPEG ~0.85.
- Оригинал хранится всегда, обработанная версия лежит отдельно и пересоздаётся из оригинала.

### 3.3. Обработка слайдов
- Текст извлекается из текстового слоя PDF через PDFKit, без модели: бесплатно и мгновенно.
- Страница отправляется в модель как картинка, только если текста почти нет (меньше порога символов) или текстовый слой похож на мусор: формулы, разорванные символы, много нераспознанных глифов. Эвристика вынесена в отдельную функцию и покрыта тестами.
- У каждого слайда есть ручной переключатель «текстовый слой / распознать как картинку» и флажок «не включать в конспект» (титульники, «Спасибо за внимание»).

## 4. Конвейер
1. Создаю лекцию: предмет (выбор из списка или новый), тема, дата (по умолчанию дата съёмки первого фото или сегодня).
2. Добавляю источники и правлю порядок.
3. **Этап 1, распознавание.** Каждая страница рукописи и каждый слайд-картинка отдельно превращаются в Markdown.
4. **Этап 2, сборка** в один чистый конспект. Режим зависит от того, что есть в лекции:
   - **только рукопись:** как в промпте сборки ниже;
   - **рукопись + слайды:** основа — рукопись. Слайды используются для сверки: помогают разобрать `[неразборчиво]` и найти ошибки. Материал, которого нет в тетради, но есть на слайдах, добавляется отдельными блоками `> 📎 Из слайдов: …`. Текст рукописи слайдами не переписывается;
   - **только слайды:** структурированный конспект по слайдам, без дописывания от себя.
   - **Длинные лекции:** если суммарный текст больше порога (настройка, по умолчанию ~40 000 символов), сборка идёт частями по страницам с перекрытием в одну страницу, затем финальный проход склейки. Для коротких лекций сборка идёт одним вызовом.
5. **Этап 3, учебные материалы.** По умолчанию запускается кнопкой, чтобы сначала проверить конспект и не тащить ошибки распознавания в карточки. В настройках есть тумблер «запускать автоматически после сборки». На вход идёт только `konspekt.md`.

### 4.1. Ручные правки, версии, устаревание
- Перед любой перезаписью результата модели (страница, конспект, учебные материалы) текущая версия сохраняется в `history/` с меткой времени.
- Если файл правился вручную (флаг в `meta.json`), перед перезаписью показывается предупреждение. В истории можно посмотреть версию и восстановить её одним кликом.
- Каждый артефакт хранит в `meta.json` хеши входных данных, из которых он получен: конспект — хеши текстов страниц и их порядок, учебные материалы — хеш конспекта. Если входные данные изменились, на вкладке появляется баннер «Устарело» с кнопкой «Пересобрать». Автоматически ничего не перезапускается.

## 5. Промпты
Промпты лежат отдельными файлами в папке данных (`<папка хранения>/_prompts/`). При первом запуске туда копируются значения по умолчанию из бандла. В настройках есть кнопка «Открыть папку промптов» и «Сбросить к умолчанию».
- Базовые файлы по этапам: `recognize.md`, `recognize-slide.md`, `assemble.md`, `assemble-with-slides.md`, `assemble-slides-only.md`, `assemble-merge-chunks.md`, `study.md`.
- Вставки по предметам: `subjects/<Предмет>.md`. Если файл есть, он подставляется в промпт. Готовые вставки для «Химия» (mhchem, валентности, ионные уравнения), «Математика» (обозначения, без упрощения выкладок) и «Физика» (единицы СИ, векторы).
- Подстановки: `{предмет}`, `{тема}`, `{вставка_предмета}`, `{страницы}`, `{конспект}`.

**Распознавание страницы (по умолчанию):**
> Это фотография рукописного конспекта студента по предмету «{предмет}». Перепиши его в Markdown максимально точно, ничего не добавляя от себя. Сохрани структуру: заголовки, списки, нумерацию. Формулы пиши в LaTeX (`$...$` в строке, `$$...$$` отдельно). Химические формулы и уравнения реакций оформляй через mhchem: `\ce{2H2 + O2 -> 2H2O}`. Рисунки и схемы опиши коротко в квадратных скобках: [Схема: ...]. Если фрагмент не читается, пиши [неразборчиво], не угадывай. Выведи только Markdown.
> {вставка_предмета}

**Сборка конспекта:** объединить страницы, убрать дубли на стыках страниц, исправить очевидные орфографические ошибки, не менять смысл и не дописывать материал. Места, где модель предполагает ошибку в самом конспекте, помечать отдельно: `> ⚠️ Возможно, ошибка: ...`.

**Учебные материалы** (ответ строго в JSON по схеме из раздела 6):
- краткое резюме на 5–10 пунктов;
- ключевые термины с определениями, взятыми из конспекта;
- 10–15 вопросов разных типов: на понимание, на применение, расчётные задачи с решением, если тема это позволяет. Решения расписаны по шагам. У каждого вопроса есть ответ и уровень сложности;
- тест из 10 вопросов с 4 вариантами ответа и объяснением правильного;
- флэш-карточки (вопрос/ответ).

Ответ валидируется: если модель обернула JSON в обычный текст или в блок ```json, JSON из него извлекается, затем проверяется по схеме. При невалидном JSON идёт одна повторная попытка, в которую передаётся текст ошибки валидации.

## 6. Хранение
Всё хранится в обычных файлах, без базы данных. Папка по умолчанию `~/Documents/Конспектор/` и меняется в настройках.

```
Конспектор/
  _prompts/…
  <Предмет>/
    <ГГГГ-ММ-ДД — Тема>/
      meta.json          # id лекции (UUID), предмет, тема, дата, порядок источников, хеши, флаги ручных правок, движки
      notes/             # раздел «Мой конспект»
        originals/<id>.<ext>
        photos/<id>.jpg   # после предобработки
        pages/<id>.md
      slides/
        originals/<file>.pdf
        images/<id>.jpg   # только для слайдов, которые распознаются картинкой
        pages/<id>.md
      konspekt.md
      study.json
      progress.json
      history/…
```

- **Отступление от первой версии ТЗ:** вместо `pages/NN.md` файлы называются по стабильному `id`, а порядок хранится в `meta.json`. Иначе при перестановке страниц пришлось бы переименовывать файлы, и правки путались бы.
- Если тема или дата меняются, папка переименовывается. Связи держатся на UUID из `meta.json`, а не на пути. Символы `/` и `:` в именах заменяются.
- **iCloud.** У меня «Документы» синхронизируются с iCloud, поэтому:
  - запись атомарная: временный файл и замена;
  - выгруженные с диска файлы (заглушки `.icloud`) скачиваются через `startDownloadingUbiquitousItem` с индикатором ожидания;
  - папка отслеживается на внешние изменения, и при изменении открытая лекция перечитывается;
  - конфликтные копии (`NSFileVersion`) показываются предупреждением, без тихой перезаписи.

### 6.1. `study.json`
У каждого элемента стабильный `id`, чтобы `progress.json` переживал правки, а в v2 из этих данных можно было собрать колоду «весь предмет».
```json
{
  "schemaVersion": 1,
  "summary": ["…"],
  "terms": [{"id": "t1", "term": "…", "definition": "…"}],
  "questions": [{"id": "q1", "type": "understanding|application|calculation", "difficulty": "easy|medium|hard", "question": "…", "answer": "…", "solution": "…или null"}],
  "quiz": [{"id": "z1", "question": "…", "options": ["…","…","…","…"], "correctIndex": 2, "explanation": "…"}],
  "flashcards": [{"id": "f1", "front": "…", "back": "…"}]
}
```
Все текстовые поля могут содержать Markdown и формулы, отображение через тот же KaTeX-рендерер.

### 6.2. `progress.json`
Для каждой карточки, вопроса и пункта теста хранятся последний результат (знаю / не знаю, верно / неверно) и дата, для каждого теста — история попыток (дата, счёт). Флажок «ошибка в вопросе» убирает элемент из подсчёта и прячет его в режиме самопроверки.

## 7. Интерфейс
- Слева сайдбар: предметы, внутри них лекции. Создание, переименование, удаление лекции (в корзину).
- Экран лекции с вкладками «Источники», «Конспект», «Вопросы», «Тест», «Карточки».
- **«Источники»:** два раздела, «Мой конспект» и «Слайды». У каждой страницы фото или слайд и распознанный текст бок о бок. Текст редактируется. У каждой страницы есть кнопки «Распознать заново», «История», управление обрезкой и поворотом. `[неразборчиво]` подсвечивается, по клику фото приближается.
- **«Конспект»:** отрисованный Markdown с формулами (WKWebView + KaTeX + mhchem) и переключатель «редактировать / просмотр». Блоки `⚠️` и `📎 Из слайдов` выделяются стилем, `[неразборчиво]` подсвечивается. Ошибки KaTeX в отдельной формуле не ломают страницу: показывается исходный LaTeX красным.
- **«Вопросы»:** список с фильтром по типу и сложности, ответы раскрываются по клику.
- **«Тест»:** по одному вопросу, варианты перемешиваются. После ответа показывается объяснение, в конце результат, есть режим «пройти только ошибки».
- **«Карточки»:** карточка переворачивается по клику или пробелу. Отмечаю «знаю / не знаю» (← / →), в конце результат, есть режим «повторить только незнакомые».
- У каждого вопроса и карточки есть флажок «ошибка в вопросе» и ручное редактирование.
- Прогресс обработки: какая страница, какой этап, какой движок, сколько прошло времени, кнопка «Отменить». Если ушли на запасной движок, это видно.
- Интерфейс на русском, светлая и тёмная тема по системе. Веб-вью тоже следует системной теме.

## 8. Экспорт
- **`.md`:** конспект как есть, с формулами.
- **PDF:** из отрендеренного конспекта, формата A4, с разбивкой на страницы, с формулами. Печатать только после того, как KaTeX закончил рендер (сигнал из JS).
- **CSV для Anki:** карточки, а по галочке ещё и вопросы. Заголовки Anki: `#separator:tab`, `#html:true`, `#tags column:3`. Теги вида `предмет::тема`. Формулы конвертируются в синтаксис MathJax: `$…$` → `\(…\)`, `$$…$$` → `\[…\]`. Проверь, поддерживает ли MathJax в Anki `\ce{}`. Если нет, укажи это в инструкции.

## 9. Настройки
- Основной и запасной движок, автопереключение при лимите.
- Пути к CLI (автопоиск + ручной путь), модель для каждого движка (если CLI позволяет выбрать), кнопка «Проверить подключение» для каждого движка: версия, логин, тестовый запрос.
- Таймаут на страницу, число параллельных вызовов (1–2), порог для сборки по частям.
- «Запускать учебные материалы автоматически».
- Папка хранения, «Открыть папку промптов», «Сбросить промпты».
- «Сохранять временные папки при ошибке» (для отладки).

## 10. Проверка
- **Юнит-тесты:** разбор JSON-ответов обоих CLI (успех, ошибка, лимит, мусор вокруг JSON), извлечение и валидация `study.json`, распознавание лимита по stderr, предобработка изображений (EXIF-поворот, HEIC→JPEG, ресайз, разбиение PDF), эвристика «текстовый слой или картинка» для слайдов, поиск бинарников (на фейковой файловой системе), хеши и устаревание, атомарная запись, конвертация формул для Anki.
- **Тестовые данные:** сгенерируй несколько изображений с текстом, формулой и уравнением реакции, а также маленький PDF со слайдами с текстовым слоем. Я дополнительно положу 2–3 реальных фото в `TestData/real/` (папка в `.gitignore`).
- **Сквозной прогон:** весь конвейер на тестовых данных обоими движками. Результаты и замеченные проблемы запиши в `docs/e2e-report.md`.
- В конце дай короткую инструкцию: как собрать, где лежит `.app`, как перенести его в «Программы», что делать, если Gatekeeper ругается.

## 13. Уточнения после согласования (2026-10-14)
Эти решения дополняют разделы выше и при расхождении имеют приоритет.

- **Запуск этапов.** Этап 1 (распознавание) стартует сам для новых страниц сразу после импорта. Этап 2 (сборка) запускается кнопкой «Собрать», когда я проверил страницы и порядок. Этап 3 остаётся как в разделе 4: кнопка или тумблер в настройках.
- **Сборка длинной лекции со слайдами.** Каждая часть рукописи получает пропорциональный срез слайдов (часть k из n — примерно k-я n-я доля слайдов по порядку) с перекрытием в несколько слайдов. Дополнительных вызовов модели для сопоставления нет.
- **Пересборка учебных материалов.** `progress.json` начинается заново. Старые `study.json` и `progress.json` уходят в `history/`. Стабильные `id` нужны для ручных правок, а не для переноса прогресса между пересборками.
- **Предметы.** Предметы создаю сам (пункт «Новый предмет» в сайдбаре), пустой предмет тоже виден в сайдбаре. Переименование предмета переименовывает папку. Удаление предмета отправляет его в корзину вместе с лекциями, только после подтверждения. При первом запуске создаются три стартовых предмета: «Общая и неорганическая химия», «Математический анализ», «Высшая алгебра».
- **Вставки по предметам.** В бандле лежит по вставке на каждый стартовый предмет (позже добавлена вставка «Дискретная математика» для одноимённого предмета): химическая (mhchem, валентности, ионные уравнения) для «Общая и неорганическая химия», математическая для «Математический анализ» и отдельно для «Высшая алгебра» (с подстройкой под каждый). Вставка «Физика» лежит образцом в `_prompts/subjects/_образцы/`. Для нового предмета файл вставки создаю сам, без него вставка пустая.
- **Дата лекции.** При создании лекции по умолчанию стоит сегодняшняя дата. Если первые импортированные фото сняты в другой день, дата один раз меняется на дату съёмки, и появляется плашка «Дата изменена по фото · Вернуть». Потом дата сама не меняется.
- **Совпадение имён папок.** Если папка `<ГГГГ-ММ-ДД — Тема>` уже есть, к имени добавляется « (2)», « (3)» и т. д.
- **Git.** Локальный репозиторий и приватный репозиторий на GitHub (через `gh`). Коммит и push после каждого зелёного этапа.
- **Подпись.** Personal Team через бесплатный Apple ID (стабильная подпись, разрешения не слетают при пересборке). Team ID лежит в `Config/Signing.xcconfig` (вне git, шаблон — `Config/Signing.example.xcconfig`); без него сборка подписывается ad-hoc.
- **Реальные фото.** Этап 0 проводится на сгенерированных картинках. Реальные фото рукописи в `TestData/real/` положу, когда попросишь: для проверки качества распознавания.
- **Название.** Приложение называется **Inkling** (ink — чернила, inkling — догадка). Имя `.app`, схема Xcode и таргет: `Inkling`, bundle id `com.nkalmykov.inkling`. Название «Конспектор» в тексте ТЗ выше означает это же приложение.
- **Папка хранения** по умолчанию `~/Documents/Inkling/` (вместо `~/Documents/Конспектор/` из раздела 6).
- **Иконка.** Монограмма: строчная «i», точка которой — капля чернил. Строгий минимализм: почти чёрный фон, светлая ножка буквы, тёплая янтарная капля. Итоговая иконка в современном стиле macOS: слоями через Icon Composer, с вариантами для светлой, тёмной и тонированной темы. На этапе 1 ставится простая заготовка, итоговая иконка делается на этапе 7.
- **Движки (изменение раздела 2 по итогам этапа 0).** Gemini CLI с 18 июня 2026 не обслуживает подписки Google AI Pro/Ultra (`IneligibleTierError`), а его замена Antigravity CLI (`agy`) отказывает аккаунту по стране (`Eligibility check failed … not currently available in your location`); подробности в `docs/cli-notes.md`. Поэтому **v1 работает на одном движке — Claude Code** (`ClaudeCodeEngine`). Протокол `AIEngine`, логика повторов и автопереключения на запасной движок, настройки «основной/запасной движок» остаются: запасной движок просто не выбран, пока его нет. `GeminiCLIEngine` в v1 не делается. Второй движок (`agy` при появлении доступа, Ollama) — в бэклоге.
- **Запасной движок Ollama (этап 8, 2026-10-14).** Решение после прогона локальных моделей на синтетике и реальных страницах (`docs/local-models.md`). Запасной движок — Ollama с моделью `inkling-ocr` (Qwen3.5-9B с настройками под распознавание; Modelfile в `docs/ollama/`). Качество на плотной рукописи заметно ниже, чем у Claude, поэтому всё, что сделано локальной моделью, помечается «Сделано локальной моделью — проверьте».
  - `OllamaEngine` ходит в HTTP API `http://127.0.0.1:11434` (`/api/chat`): картинки в base64, рассуждения выключены (`think: false`), для JSON передаётся схема в `format`. Картинки меньше 1600 px по длинной стороне перед отправкой увеличиваются (до 2×): на мелких скриншотах это заметно снижает ошибки.
  - Сервер запускает само приложение (`ollama serve`), когда нужен локальный движок и сервер не отвечает; при выходе гасит его, только если запускало само. Бинарник `ollama` ищется так же, как `claude` (раздел 2.4), путь можно задать вручную.
  - К Ollama одновременно идёт не больше одного вызова. Сборка на локальном движке идёт частями от 15 000 символов (или от меньшего порога из настроек), таймауты в 3 раза длиннее.
  - Обёртка ```` ```markdown ```` снимается и при распознавании страниц.
  - При распознавании локальной моделью из промпта убирается название предмета (с ним модель изредка сочиняет учебник по предмету вместо переписывания), а ответ ограничен 4 096 токенами. JSON-схема, если сборка модели её не поддерживает, передаётся текстом в промпте.
  - **Ручной выбор модели.** В настройках: модель Claude из списка (Sonnet, Opus, Haiku или своя строка), модель Ollama из установленных. На панели лекции меню «Модель»: «Авто» (основной → запасной), «Только Claude», «Только локальная». Выбор общий для приложения и действует на новые запуски.
  - Новые ошибки: «Ollama недоступна» (нет бинарника или сервер не поднялся) и «Модель не установлена в Ollama», обе без повторов и без перехода на другой движок.
- **Дизайн-система (2026-10-15).** Минимальная версия macOS поднята до 26 (вместо 14 из раздела 1): Liquid Glass и новые стили SwiftUI без `if #available`. Стекло только системное, своего `glassEffect` нет. Акцент свой: янтарь капли из иконки (`#F5B83D` в тёмной теме, затемнённый в светлой). Цвет есть только у ошибки (красный) и успеха (зелёный), предупреждения нейтральные; исключение — заметная пометка «Сделано локальной моделью — проверьте». Интерфейс набирается SF, тексты для чтения (конспект, вопросы, карточки) — New York. Токены и компоненты лежат в `Inkling/DesignSystem/`, описание в `docs/design-system.md`.
- **«Дополнить» (2026-10-15).** Отдельный проход поверх готового конспекта по кнопке на вкладке «Конспект»; исключение из правила «ничего не дописывать», которое для обычной сборки остаётся.
  - Модель добавляет помеченные блоки в тот же `konspekt.md`: `## 🧭 Главное` (резюме в начале), `> 💡 Пояснение`, `> 📝 Пример`, `> 🔗 Связи`, графики (```` ```plot ````, JSON с формулами) и схемы (```` ```svg ````), а термины выделяет `**жирным**`. Блоки `⚠️` и `📎` остаются блоками сборки.
  - Текст автора не меняется: код сравнивает текст без добавлений и без `**` с исходным; при расхождении одна повторная попытка, затем ошибка, файл не трогается (`Enrichment.preservesAuthorText`).
  - Второй вызов модели проверяет добавленное и возвращает номера ошибочных блоков (JSON); они вырезаются. Если проверка не удалась, дополнение не сохраняется.
  - Только через облачный движок (`AIRequest.cloudOnly`: Claude Code или Codex): без перехода на Ollama, при выбранном «Только локальная» кнопка возвращает понятную ошибку.
  - Частота: не больше одного блока на раздел и только там, где он что-то проясняет; графиков и схем обычно 0–3 на конспект (правило в промпте `enrich.md`).
  - Графики считаются в приложении (`diagram.js`): модель присылает выражения, а не координаты. Схемы SVG проходят белый список элементов и атрибутов; сети нет, CSP прежний.
  - Пересборка конспекта создаёт описание заново, дополнение сбрасывается, прежняя версия уходит в «Историю». Ручная правка дополнение не сбрасывает; повторное «Дополнить» после ручной правки идёт через подтверждение, версия сохраняется в истории.
  - Учебные материалы строятся по тексту без добавлений (`Enrichment.removing`), хеш считается так же, поэтому «Дополнить» не делает материалы устаревшими.
- **PDF-экспорт (2026-10-16).** «Конспект в PDF» не спрашивает место: файл `<Тема> — <Предмет> — <ГГГГ-ММ-ДД>.pdf` (тема с большой буквы) сразу кладётся в `~/Documents/Конспекты/` (папка создаётся сама, повторный экспорт той же лекции заменяет файл) и показывается в Finder. Markdown и Anki-CSV по-прежнему через панель сохранения.
- **Догадки модели и режим «Подробно» (2026-10-16).** Правило «не угадывай» смягчено: если слово или символ читается плохо, но уверенно восстанавливается по смыслу, соседним строкам и предмету, Claude пишет `[?слово]` (для формулы `[?$…$]`); безнадёжные места по-прежнему `[неразборчиво]`. Догадки подчёркнуты точками в конспекте и в редакторе страницы, сборка их сохраняет, а слайды могут подтвердить и заменить без скобок. Кнопка «Подробно» на странице тетради читает её шестью перекрывающимися фрагментами (сетка 3×2, перекрытие 20 % по высоте и 25 % по ширине) исходного фото (до 4 500 px по длинной стороне) одним запросом `recognize-detailed.md`; только через Claude, вдвое больший таймаут. Замер на синтетической странице 3000×4200 px (100 строк с двузначными индексами кеглем 10 px): обычное распознавание — 58 строк из 100 дословно, три горизонтальные полосы — 96, сетка 3×2 — 100. На страницах с крупным текстом разницы нет (52 из 52 у всех вариантов), на низком разрешении (скриншоты ≤1 800 px) выигрыша тоже нет: режим нужен для крупных фото с телефона и мелкого почерка.
- **Codex (ChatGPT) как третий движок (2026-10-17).** Для тех, у кого есть подписка ChatGPT, а не Claude: `CodexEngine` вызывает `codex exec` (флаги и формат событий — `docs/cli-notes.md`, раздел «Codex CLI»). Вход делает пользователь командой `codex login`; ключи API и `OPENAI_*` в процесс не передаются. Выбирается как основной или запасной движок и режимом «Только Codex» в меню «Модель»; облачные действия («Дополнить», «Подробно») работают и через него. **Не проверен вживую** (у автора нет подписки): помечен так в настройках и в меню, схемы JSON передаются текстом, модель по умолчанию выбирает сам Codex. Тесты идут на настоящем выводе без входа и на синтетических событиях.
